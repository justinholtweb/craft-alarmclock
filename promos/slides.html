Alarm Clock

Scheduled publishing that tells you it happened.

Craft publishes your 9am post at 9am. Nothing clears a cache, nothing is logged and nobody is told — because as far as Craft is concerned, no row changed.

Free  ·  single edition Craft 5.3+  ·  PHP 8.2+  ·  no dependencies
The whole idea
At 09:00, Craft does entry.status = live At 09:00, Alarm Clock does everything else

Craft caps a {% cache %} block at the soonest getExpiryDate() of the elements it rendered — and a pending entry is returned by no live query, so your cached listing has no idea a post is coming.

Detection

Three triggers,
one ledger

Which trigger works depends on hosting you cannot see from inside a plugin. So all three run.

  • Console — exact, free, needs real cron
  • Queue — a job that reschedules itself
  • Front-end — works everywhere, and runs after the response has gone out
UNIQUE (elementId, siteId, transition, scheduledFor)
1Console tick09:00:04 · cronRecorded
2Queue tick09:00:11 · self-rescheduling jobAlready handled
3Front-end tick09:00:12 · after the response was sentAlready handled

Three processes checking-then-inserting cannot be made safe in application code. The insert is the thing that has to be won, so the losers are told so.

Cache invalidation

Clears exactly
what went stale

The same tags an ordinary save would clear — the ones your listing query registered when it built the page.

  • Bigger hammers available for raw SQL and search indexes
  • Optional URL warming, so the first real visitor gets a warm page

Follow-up work

Retries the half
that failed

A crossing is a fact and cannot fail. Everything done about it can — so they are separate rows.

  • Exponential, capped and jittered backoff
  • A task whose runner died is reclaimed, not stranded
  • Every failure listed with its error and a retry button
TaskAttemptStatus
invalidate-caches1Done
warm-urls1Done
notify1Done
webhook3Retrying in 4m

The webhook being down for an hour does not hold up the cache clear, and a person can see which half went wrong.

Scheduled drafts

Replace what’s
live, later

Craft can schedule an entry’s first appearance. It cannot say “swap in this draft at nine tomorrow”.

  • From the draft’s own sidebar, or from the console
  • Validated before it is applied, so a failure says something you can act on
Alarm Clock
2026-09-01 09:00 AM Schedule

Until then it is an ordinary draft. Nobody has to keep a tab open at nine in the morning.
